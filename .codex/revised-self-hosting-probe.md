# Revised Self-Hosting Probe

## Conditions

A fresh agent with no prior Stack Studio discussion received the self-hosting
prompt from `evaluation-scenarios.md`. It could inspect only Stack Studio, could
not edit files, and was asked to orient and choose the first useful work unit.

## Observed journey

The agent read `AGENTS.md` and `README.md`, selected `create-stack` because the
README names it as the end-to-end authority, followed its initializer,
persistent-state, iteration-pattern, authoring, and auditing links, then
inspected the manifests and repository-local evaluation evidence.

It identified `create-stack` as the single authority for continued stack-level
progress. It treated the target repository as implementation truth, the frontier
as supplemental decision state, the human as the authority for consequential
outcome judgments, `writing-skills` as the individual-skill authority, and
`audit-and-publish` as structural and release-readiness support.

The agent found explicit transitions from `create-stack` to every supporting
capability and correctly treated the generic transition handlers as conditional
parts of the loop rather than parallel project workflows. It also found
`create-stack`'s explicit ownership of stack-level behavioral evaluation.

The agent distinguished release readiness from publication and observed that an
actual versioning, registry, marketplace, or release transaction remains outside
the current implementation.

## Scenario 3 check results

- **Pass — recognizes the recursive task:** The agent used Stack Studio's live
  workflow and repository-local self-hosting evidence.
- **Pass — establishes outcome and preservation evidence first:** It inspected
  the frontier and fixed evaluation scenario before selecting further edits.
- **Pass — traces current authorities and edges:** It identified the former
  split as historical and absent from the live skill inventory.
- **Not fully exercised — treats `project-skills` as lineage rather than an
  obligation:** The live guidance says to adapt the pattern rather than reproduce
  generic skills, but the probe was prohibited from inspecting sibling repos.
- **Pass — one continued-progress authority and explicit transitions:** It named
  `create-stack` and enumerated the supporting edges without inventing a handoff.
- **Pass — stack-level coherence owner and evidence path:** It found the fresh-
  agent, end-to-end evaluation procedure and its fixed scenario checks.
- **Not exercised — preserves deterministic tools:** The probe made no edits and
  therefore could not test preservation after structural change.
- **Pass — lower inference burden than baseline:** The agent derived the intended
  topology from explicit instructions instead of reconciling `create-stack` with
  a second controller.

This was an orientation checkpoint, not a complete pass of the self-hosting
scenario. Six checks passed and two remain unexercised.

## Remaining observations

- `audit-and-publish` is named more broadly than its implemented release-
  readiness behavior.
- `stack-studio-init` verifies only that `create-stack` is visible, not that all
  supporting capabilities are discoverable.
- The evaluation scenarios have no repeatable runner or persisted scoring
  format; this probe was captured and judged manually.
- Cross-harness claims remain structural rather than live semantic verification
  in every harness.
